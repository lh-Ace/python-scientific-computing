# Outside material and intellectual provenance

## Our approach

This is an independent course informed by external sources. It is **not an aggregate of copied repositories** or a git merge of unrelated histories.

Allowed by default:
- Link to sources and cite authors.
- Write original lesson explanations, exercises, mathematics, diagrams, and code.
- Describe an algorithm, its history, and why it is implemented a certain way.
- Compare behavior with existing libraries by installing them *when the curriculum calls for them*.

Requires individual license review:
- Republishing source code, long text, diagrams, worked examples, whole notebooks, datasets, and figures from other resources.
- Inserting a third-party project as a submodule/vendor directory or copying example solutions.
- Relicensing adapted materials under a course license.

Illustrative examples: the code and book text of Python Data Science Handbook have different licenses; From Python to NumPy separates book and code terms. CC BY-NC / ND / SA terms may materially restrict redistribution or adaptation. For this reason the starting course links to originals and ships **no borrowed content**.

## Course-license decision

Leave the course unlicensed/private until the author deliberately selects terms. If publishing later, revisit attribution and any embedded third-party content before applying a license.

## Citation format in lessons

- Reference: Author / project, title, URL.
- Relevant section: specific chapter/function/documentation subsection.
- Role: e.g., historical background, API semantics, problem formulation, comparison.
- Adaptation: original explanation, recreated example, cited quotation where properly permitted.
- Retrieval/version: as needed for fast-changing API specifications.
