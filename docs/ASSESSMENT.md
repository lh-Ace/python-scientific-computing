# Assessment and proficiency gates

## Each module's evidence

- Pre-check (diagnostic, ungraded): verify prerequisites before teaching new concepts.
- Frequent tiny exercises: predict, implement, explain, change an input, observe.
- Debugging tasks: analyze a faulty small program and justify the fix.
- Concept checks: explain code behavior without running it.
- Practical lab: original code, tests, notes, and evidence.
- Module examination: new problems, not memorized replicas of demonstrations.

## Rubric (100 points)

| Dimension | Points | What counts |
| --- | ---: | --- |
| Conceptual and mathematical understanding | 25 | Correct explanations, definitions, assumptions, derivations when relevant |
| Independent program construction | 25 | Uses currently taught ideas correctly without reproducing a template blindly |
| Correctness and testing | 20 | Demonstrates actual behavior, input assumptions, edge cases, reproducibility |
| Clarity and engineering | 15 | Readable code, appropriate structure, concise comments and documentation |
| Reflection and transfer | 15 | Explains mistakes, evaluates alternatives, adapts to a fresh related problem |

- **90–100**: strong mastery, subject to independent oral/written verification.
- **80–89**: proficient; may advance after identified issues are resolved.
- **70–79**: developing; focused revision required.
- **Below 70**: repeat targeted fundamentals before advancing.

A module is not verified until its foundational competencies are demonstrated, even if the numerical score is high. Assessments are course-internal and not an institutional credential.

## Module 01 sample assessment outline (not assigned yet)

1. Explain `print()`, expression evaluation, and a program's entry point.
2. Predict type and value of arithmetic expressions.
3. Trace variable assignments, including overwriting names.
4. Write a conditional using correct boolean reasoning.
5. Implement a loop without off-by-one mistakes.
6. Write and test a function for a clearly stated mathematical rule.
7. Work with a list of numerical measurements safely.
8. Explain a traceback and fix an intentional bug.
9. Read and write a tiny text file using appropriate error handling.
10. Solve a new small task, explain it without running the code first, then verify experimentally.

Rubrics are stable; assessment prompts may change to ensure genuine transfer. Do not commit solution keys into the main learner branch before evaluation.
