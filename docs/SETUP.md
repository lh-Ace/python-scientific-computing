# 00 — Setup and the reasoning behind it

## Prerequisite

`uv` is already installed. Check with:

```bash
uv --version
```

We use `uv` as a **project and Python environment manager**, not as a prerequisite to learning numerical libraries. An environment keeps project dependencies isolated, and `pyproject.toml` declares what this project needs. The `.python-version` file selects our initial CPython 3.13 learning target. You can keep a different Python installed globally.

## First local run

Run these commands from the repository's top-level directory:

```bash
uv python install 3.13           # safe if already available
uv sync                        # creates .venv; installs no scientific libraries
uv run python --version
uv run python lessons/01-python-foundations/01-01-running-python/hello.py
uv run python -m unittest discover -s tests -v
```

`uv sync` creates or updates an isolated project environment. `uv run` executes within it. Our first programs use only built-in Python capabilities, so NumPy, SciPy, Jupyter, and PyTorch are intentionally absent.

You can also run the program with an explicitly chosen interpreter once you understand which Python executable is active. We will study the distinctions between interpreter, executable, virtual environment, and package manager.

## About the lock file

`uv.lock` records the resolved environment for reproducibility. When dependencies are added later, update and commit it. Do not edit it by hand. `uv.lock` may be generated by `uv sync` if it is not present.

## Publishing to GitHub

The connected GitHub account is available for reading and reviewing repository content, but creating a *new repository* is not provided by the connected GitHub actions used during setup. Create an **empty private** repository named `python-scientific-computing` on GitHub, without initializing it with README/license/gitignore (our local scaffold already provides those files).

Then, from the local repository directory:

```bash
git init -b main
git add .
git commit -m "course: establish Python scientific computing foundations"
git remote add origin https://github.com/YOUR-USERNAME/python-scientific-computing.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your actual GitHub account login. Git may prompt you to authenticate. If you already have a repository, don't initialize or overwrite it without checking its contents first.

If you have GitHub CLI (`gh`) and are authenticated, an alternative is `gh repo create python-scientific-computing --private --source=. --remote=origin --push` *after* the local initial commit.

## Working routine

Before every lesson: `git status`; open the lesson instructions. During the lesson: edit the lesson's program and append journal notes. After meaningful progress: `git diff`, run the program, commit with a descriptive message. For verified milestone: run any checks, write a reflection, and record reviewer feedback before marking the module complete.

## Troubleshooting

- `uv: command not found`: check your installation and shell PATH using the [official uv docs](https://docs.astral.sh/uv/getting-started/installation/).
- Wrong interpreter version: compare `uv run python --version` with `python3 --version`. The environment may use a different Python from the system.
- Git push rejected: inspect the remote and your GitHub authentication. Do not force-push over existing work.
- `python` path errors: run commands from the repository root; lessons rely on relative paths.
